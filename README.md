# 🛠️ แอปแจ้งซ่อมออนไลน์ (Repair Report Mini App)

แอปสำหรับแจ้งซ่อม พร้อมระบุตำแหน่งบนแผนที่ แนบรูปภาพ ติดตามสถานะแบบเรียลไทม์
และหน้าแอดมินสำหรับดูสรุป/จัดการงานซ่อมทั้งหมด

รองรับการใช้งานเป็น **เว็บแอปทั่วไป** และ **LINE Mini App (LIFF)**

---

## 📁 โครงสร้างไฟล์

```
repair-app/
├── index.html          หน้าแจ้งซ่อม + ติดตามสถานะ (สำหรับผู้แจ้ง)
├── admin.html           หน้าแดชบอร์ดแอดมิน
├── js/
│   ├── config.js         ← ใส่ค่า API Key ต่างๆ ที่นี่ (มี CATEGORIES_SEED = ประเภทงานเริ่มต้น)
│   ├── firebase-init.js
│   ├── categories.js      จัดการ "ประเภทงาน" ใน Firestore (เพิ่ม/แก้ไข/ปิดใช้งานได้จากหน้าแอดมิน)
│   ├── projects.js        จัดการ "โปรเจกต์" ใน Firestore (เพิ่ม/แก้ไข/ปิดใช้งานได้จากหน้าแอดมิน)
│   ├── report.js
│   ├── track.js
│   ├── admin.js
│   ├── map-picker.js
│   ├── tabs.js
│   ├── i18n.js
│   └── utils.js
├── css/style.css
├── firestore.rules
└── firebase.json
```

> **หมายเหตุเรื่องรูปภาพ:** แอปนี้ไม่ใช้ Firebase Storage เพราะ Google กำหนดให้ต้องอัปเกรดโปรเจกต์เป็นแผน
> Blaze (ต้องผูกบัตรเครดิต) ถึงจะเปิดใช้ Storage ได้ แม้จะมี free quota ก็ตาม เพื่อให้ใช้งานได้ฟรี 100%
> โดยไม่ต้องผูกบัตร รูปที่แนบจะถูกบีบอัดฝั่งเบราว์เซอร์ (ย่อขนาด + ลดคุณภาพ) แล้วเก็บเป็น base64
> ตรงใน Firestore แทน (ดู `js/image-compress.js`) ข้อจำกัดคือ Firestore เก็บได้เอกสารละไม่เกิน 1MB
> จึงรองรับรูปคุณภาพพอดูได้ 1–5 รูปต่อรายการ หากในอนาคตต้องการรูปคุณภาพสูงขึ้นจำนวนมาก
> แนะนำให้อัปเกรดเป็น Blaze แล้วสลับกลับไปใช้ Firebase Storage

## ขั้นตอนที่ 1: สร้างโปรเจกต์ Firebase (ฟรี ไม่ต้องผูกบัตร)

1. ไปที่ https://console.firebase.google.com → **สร้างโปรเจกต์ (Add project)**
2. ตั้งชื่อโปรเจกต์ เช่น `repair-report-app` → กด Create
3. ในเมนูซ้าย เปิดใช้งานบริการต่อไปนี้ (อยู่ในแผนฟรี Spark ทั้งหมด ไม่ต้องผูกบัตร):
   - **Firestore Database** → Create database → เลือกโหมด Production → เลือก location (เช่น `asia-southeast1`)
   - **Authentication** → Get started → เปิด Sign-in method: **Email/Password**
   - **Hosting** → Get started (ไว้ deploy ทีหลัง)
4. ไปที่ **Project settings (ไอคอนเฟือง) > General** → เลื่อนลงไปที่ "Your apps" → กดไอคอน **</>** (Web app) → ตั้งชื่อ (เช่น "repair-web") → Register app
5. คัดลอกค่า `firebaseConfig` ที่ได้ (apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId) ไปใส่ในไฟล์ **`js/config.js`** ส่วน `FIREBASE_CONFIG`

### ตั้งค่ากฎความปลอดภัยของฐานข้อมูล (สำคัญ — ต้องทำ ไม่งั้นแอปใช้งานไม่ได้)
1. ไปที่เมนู **Firestore Database > กฎ (Rules)** ในโปรเจกต์ Firebase ของคุณ
2. เปิดไฟล์ **`firestore.rules`** ที่แนบมาในซิปนี้ → คัดลอกเนื้อหาทั้งหมด
3. วางแทนที่เนื้อหาเดิมในกล่องกฎบนเว็บ Firebase Console → กด **Publish**

> หน้าแอดมินของแอปนี้ไม่ใช้ระบบล็อกอิน/รหัสผ่านแล้ว (ดูหัวข้อ "ระบบแอดมิน" ด้านล่าง)
> จึงไม่ต้องสร้างบัญชีผ่าน Authentication อีกต่อไป

## ขั้นตอนที่ 2: แผนที่ (ไม่ต้องตั้งค่าอะไร)

แอปนี้ใช้ **OpenStreetMap + Leaflet** สำหรับระบุตำแหน่งและค้นหาสถานที่ ซึ่งฟรี 100%
ไม่ต้องขอ API Key และไม่ต้องผูกบัตรเครดิตใดๆ (ต่างจาก Google Maps ที่ต้องเปิด billing
บน Google Cloud แม้จะมีเครดิตใช้ฟรีรายเดือนก็ตาม) ใช้งานได้ทันทีไม่ต้องแก้ไข `config.js`

> หมายเหตุ: Nominatim (ผู้ให้บริการค้นหา/ระบุที่อยู่ของ OpenStreetMap) มีข้อจำกัดการเรียกใช้งาน
> ที่เหมาะกับแอปขนาดเล็ก-กลาง หากมีผู้ใช้จำนวนมากในอนาคต ควรพิจารณาใช้บริการ geocoding แบบมีเครดิต

## ขั้นตอนที่ 3: Deploy เว็บให้ได้ลิงก์ก่อน (ต้องมีลิงก์ก่อนถึงจะสร้าง LIFF ได้)

LIFF ต้องผูกกับ URL จริงที่เข้าได้จากอินเทอร์เน็ต (ต้องเป็น **https://**) เลือกวิธีใดวิธีหนึ่ง:

**ทางเลือกที่ง่ายที่สุด — Netlify Drop (ไม่ต้องติดตั้งอะไร ไม่ต้องมีบัญชีก็ได้)**
1. ไปที่ https://app.netlify.com/drop
2. ลากโฟลเดอร์ `repair-app` (หรือไฟล์ zip ที่ได้รับ) ไปวางในหน้านั้น
3. รอสักครู่ จะได้ลิงก์ทันที เช่น `https://random-name-12345.netlify.app`

**ทางเลือกที่เป็นทางการ — Firebase Hosting (ผูกกับโปรเจกต์ Firebase เดิม)**
```bash
npm install -g firebase-tools
cd repair-app
firebase login
firebase use --add          # เลือกโปรเจกต์ Firebase ที่สร้างไว้
firebase deploy
```
หลัง deploy สำเร็จ จะได้ URL ลักษณะ `https://your-project.web.app`
- หน้าแจ้งซ่อม: `https://your-project.web.app/`
- หน้าแอดมิน: `https://your-project.web.app/admin`

> จดลิงก์ที่ได้ไว้ก่อน จะต้องใช้ในขั้นตอนถัดไป

## ขั้นตอนที่ 4: สร้าง LINE LIFF App (ทำให้เป็น LINE Mini App) — ต้องทำเองผ่านบัญชี LINE ของคุณ

1. ไปที่ https://developers.line.biz/console/ → ล็อกอินด้วยบัญชี LINE ของคุณ (หรือของบริษัท)
2. กด **Create** สร้าง **Provider** ใหม่ (ถ้ายังไม่มี) — ตั้งชื่ออะไรก็ได้ เช่น ชื่อบริษัท
3. ภายใต้ Provider นั้น กด **Create a new channel** → เลือกประเภท **LINE Login**
   - กรอกชื่อ Channel เช่น "แจ้งซ่อมออนไลน์", เลือกหมวดหมู่/หมวดย่อยตามจริง, ยอมรับเงื่อนไข → Create
4. เข้าไปที่ Channel ที่สร้าง → แท็บ **LIFF** → กด **Add**
   - LIFF app name: แจ้งซ่อมออนไลน์
   - Size: **Full**
   - Endpoint URL: **วางลิงก์ที่ได้จากขั้นตอนที่ 3** เช่น `https://random-name-12345.netlify.app`
   - Scope: ติ๊ก **profile** และ **openid** (จำเป็น เพื่อดึงชื่อ/รูปผู้ใช้มาเติมในฟอร์มอัตโนมัติ)
   - Bot link feature: เลือก Off ได้ถ้ายังไม่มี LINE OA
   - กด Add
5. คัดลอกค่า **LIFF ID** ที่ได้ (หน้าตาแบบ `1234567890-AbCdEfGh`)
6. เปิดไฟล์ **`js/config.js`** แล้วนำ LIFF ID ไปใส่แทนที่บรรทัด:
   ```js
   export const LIFF_ID = "1234567890-AbCdEfGh"; // ← ใส่ค่าที่คัดลอกมา
   ```
7. อัปโหลดไฟล์ที่แก้แล้วขึ้น hosting เดิมอีกครั้ง (ลาก-วางที่ Netlify Drop ใหม่ หรือ `firebase deploy` ใหม่)
8. เปิดลิงก์ผ่านแอป LINE (ส่งลิงก์ไปแชทตัวเอง/OA แล้วกดเปิด) จะเห็นแอปทำงานเป็น LINE Mini App เต็มรูปแบบ

**สิ่งที่แอปนี้ทำอัตโนมัติเมื่อเปิดผ่าน LINE แล้ว (ทำไว้ให้แล้วในโค้ด ไม่ต้องแก้อะไรเพิ่ม):**
- ล็อกอิน LINE ให้อัตโนมัติเมื่อเปิดลิงก์ครั้งแรก (ผ่าน `liff.login()`)
- ดึงชื่อและรูปโปรไฟล์ LINE มาแสดงที่หัวแอป และเติมลงช่อง "ชื่อผู้แจ้ง" ให้อัตโนมัติ (ผู้ใช้ยังแก้ไขเองได้)
- บันทึก LINE userId / ชื่อ / รูปโปรไฟล์แนบไปกับรายการแจ้งซ่อมแต่ละรายการ ให้แอดมินดูอ้างอิงได้
- มีปุ่ม "ปิดหน้าต่างนี้" หลังแจ้งซ่อมสำเร็จ เพื่อปิดกลับไปที่แชท LINE (แสดงเฉพาะตอนเปิดผ่านแอป LINE เท่านั้น)

> หากยังไม่พร้อมทำ LIFF ตอนนี้ ปล่อย `LIFF_ID = ""` ไว้ได้ แอปจะทำงานเป็นเว็บแอปปกติ เปิดผ่านเบราว์เซอร์ได้ทันที โดยไม่มีผลกระทบใดๆ

> **ทำไมต้องทำขั้นตอนนี้เอง:** การสร้าง Provider/Channel ต้องล็อกอินด้วยบัญชี LINE ส่วนตัวของคุณและกดยอมรับเงื่อนไขของ LINE เอง จึงเป็นขั้นตอนที่มอบหมายให้ผู้อื่นทำแทนไม่ได้ แต่ใช้เวลาไม่เกิน 5 นาที และทำครั้งเดียวจบ

### (ทางเลือกเพิ่มเติม) เปิดหน้าแอดมินผ่านแอป LINE ได้ด้วย

ถ้าต้องการให้ทีมงานเปิด `admin.html` ผ่านแอป LINE ได้เช่นกัน ให้สร้าง **LIFF app ที่สอง** แยกต่างหาก
(ภายใต้ Channel เดิมก็ได้) โดยทำซ้ำขั้นตอนที่ 4 อีกครั้ง แต่ตั้งค่า Endpoint URL เป็นลิงก์หน้าแอดมิน
เช่น `https://your-site.netlify.app/admin.html` แล้วนำ LIFF ID ที่ได้ไปใส่ที่ `js/config.js`:

```js
export const LIFF_ID_ADMIN = "1234567890-XxYyZzWw"; // ← LIFF ID ของหน้าแอดมิน
```

> **สำคัญ:** LINE เป็นเพียง "ช่องทางเข้าถึง" หน้าแอดมินเท่านั้น ไม่ได้แทนที่ระบบสิทธิ์แอดมิน —
> เมื่อเปิดผ่าน LINE แล้ว ทีมงานยังคงต้องล็อกอินด้วยอีเมล/รหัสผ่าน (Firebase Auth) ตามปกติทุกครั้ง
> เพื่อความปลอดภัยของข้อมูล ถ้าไม่ต้องการฟีเจอร์นี้ ปล่อย `LIFF_ID_ADMIN = ""` ไว้ได้ตามปกติ

## ระบบแอดมิน (ไม่ใช้ล็อกอิน/รหัสผ่านแล้ว)

หน้าแอดมินเปลี่ยนจากล็อกอินด้วยอีเมล/รหัสผ่าน มาเป็น **"เลือกชื่อ"** จากรายชื่อทีมงานแทน
เพื่อความสะดวก ไม่ต้องจำรหัสผ่าน แต่ระบบยังบันทึกไว้เสมอว่าใครเป็นคนแก้ไขข้อมูลแต่ละรายการ
(ช่อง "แก้ไขล่าสุดโดย" จะขึ้นรหัส+ชื่อของคนที่เลือกไว้)

**เพิ่ม/ลบ/แก้ไขรายชื่อแอดมิน** ได้ที่ไฟล์ `js/config.js` ส่วน `ADMINS`:
```js
export const ADMINS = [
  { id: "001", name: "K.Eddie" },
  { id: "002", name: "K.Peggy" },
  // เพิ่มรายชื่อใหม่ต่อท้ายได้เลย
];
```
แก้ไขแล้ว deploy ไฟล์ใหม่ทับของเดิม (ลาก zip ไปที่ Netlify Drop หรือ `firebase deploy` ใหม่) เป็นอันเสร็จ

> ⚠️ **ข้อควรระวังด้านความปลอดภัย:** เพราะไม่มีรหัสผ่านแล้ว **ใครก็ตามที่มีลิงก์หน้าแอดมิน
> (`/admin` หรือ `admin.html`) จะเข้าดู/แก้ไขรายการแจ้งซ่อมทั้งหมดได้ทันที** โดยไม่ต้องพิสูจน์ตัวตน —
> การ "เลือกชื่อ" เป็นเพียงการบันทึกว่าใครแก้ไข ไม่ใช่การล็อกไม่ให้คนอื่นเข้า
> จึงควรส่งลิงก์หน้าแอดมินให้เฉพาะทีมงานเท่านั้น อย่าเผยแพร่ต่อสาธารณะหรือปนกับลิงก์หน้าแจ้งซ่อม
> ถ้าต้องการความปลอดภัยสูงขึ้นในอนาคต (เช่น มีข้อมูลอ่อนไหวมากขึ้น) สามารถกลับไปใช้ระบบล็อกอิน
> ด้วยอีเมล/รหัสผ่านแบบเดิมได้ แจ้งมาได้เสมอ

## ฟีเจอร์หลัก

**ฝั่งผู้แจ้ง**
- **เลือกโปรเจกต์ก่อนเสมอ** (ฟิลด์แรกของฟอร์ม) — โปรเจกต์เป็นรายการที่แอดมินสร้างไว้ล่วงหน้าเท่านั้น
  (ไม่ให้พิมพ์ชื่อเองอิสระ) เพื่อให้ข้อมูลแยกเป็นแต่ละโปรเจกต์ได้ถูกต้อง ไม่สะกดเพี้ยน/ปนกัน — ถ้ายังไม่มี
  โปรเจกต์ในระบบเลย จะมีข้อความแจ้งให้ติดต่อแอดมินให้เพิ่มก่อน
- กรอกชื่อสถานที่ ระบุตำแหน่งบนแผนที่ OpenStreetMap (ค้นหา/ลากหมุด/ใช้ตำแหน่งปัจจุบัน)
- กรอกชื่อผู้แจ้ง รายละเอียดปัญหา วันที่แจ้ง วันที่ต้องการเสร็จ
- เลือกประเภทงาน (ระดับย่อยรองจากโปรเจกต์): ประปา / ไฟฟ้า / บิ้วอิน / แอร์ / สุขภัณฑ์ / สี / กระจก / ม่าน /
  ฝ้า / ทั่วไป / อื่นๆ (ระบุเอง) — รายการนี้ไม่ตายตัว แอดมินเพิ่มประเภทงานใหม่เองได้ตลอดเวลาโดยไม่ต้องแก้โค้ด
  (ดูหัวข้อ "ฟีเจอร์หลัก" ฝั่งแอดมินด้านล่าง)
- แนบรูปได้ 1–5 ภาพ
- รับเลขที่แจ้งซ่อมไว้ติดตามสถานะแบบเรียลไทม์ (ไม่ต้องล็อกอิน) — หน้าติดตามสถานะจะโชว์ชื่อโปรเจกต์ของ
  รายการนั้นให้ด้วย

**ฝั่งแอดมิน**
- เข้าใช้งานด้วยการ "เลือกชื่อ" จากรายชื่อทีมงาน ไม่ต้องล็อกอิน/จำรหัสผ่าน (ดูหัวข้อ "ระบบแอดมิน" ด้านล่าง)
- **ตัวสลับโปรเจกต์ (Project Switcher)** อยู่ด้านบนสุดของแดชบอร์ด เลือกโปรเจกต์ใดโปรเจกต์หนึ่งแล้ว
  สถิติ/กราฟ/ตาราง/ตัวกรอง/ส่งออก Excel **ทั้งหมด** จะแสดงเฉพาะรายการของโปรเจกต์นั้นเท่านั้น ไม่ปนกับ
  โปรเจกต์อื่นเลย เลือก "ทุกโปรเจกต์" เพื่อดูภาพรวมรวมทุกโปรเจกต์ หรือ "(ไม่ระบุโปรเจกต์)" เพื่อดูเฉพาะ
  รายการเก่าก่อนมีฟีเจอร์นี้ — ระบบจะจำโปรเจกต์ที่เลือกไว้ล่าสุดในเครื่องนั้น ไม่ต้องเลือกใหม่ทุกครั้ง
- **จัดการโปรเจกต์ได้เอง** (คลิกเปิดหัวข้อ "📁 จัดการโปรเจกต์" ในแดชบอร์ด) เพิ่มโปรเจกต์ใหม่ได้ทันที
  (ตั้งชื่อ + เลือกสี) แก้ไขชื่อ/สีของโปรเจกต์เดิม หรือ "ปิดใช้งาน" โปรเจกต์ที่จบงานแล้ว (ซ่อนจากฟอร์ม
  แจ้งซ่อมใหม่ แต่ยังเลือกดูได้ในตัวสลับโปรเจกต์เหมือนเดิม ไม่กระทบข้อมูลเก่า)
- ดูสรุปรายวัน/รายสัปดาห์/รายเดือน พร้อมกราฟตามประเภทงาน (ขอบเขตตามโปรเจกต์ที่เลือกไว้)
- ดูรายการงานซ่อมทั้งหมดแบบเรียลไทม์ ค้นหา/กรองตามสถานะและประเภทงาน (เป็นตัวกรอง "ระดับย่อย" ภายใน
  โปรเจกต์ที่เลือกไว้อีกที) เห็นคอลัมน์ "โปรเจกต์" ในตารางด้วย
- แก้ไขข้อมูลได้ทุกช่อง (รวมถึงย้ายรายการไปโปรเจกต์อื่นได้ถ้าเลือกผิดตอนแจ้ง) เปลี่ยนสถานะ (เสร็จแล้ว /
  รอแก้ไข / ส่งต่อให้แผนกอื่น + ระบุแผนก)
- แจ้งเตือนงานที่เกินกำหนดส่งมอบ (ไฮไลต์สีแดง)
- **จัดการประเภทงานได้เอง** (คลิกเปิดหัวข้อ "🗂️ จัดการประเภทงาน" ในแดชบอร์ด) เพิ่มประเภทงานใหม่ได้
  ทันที (ตั้งชื่อ/เลือกไอคอน/สี) แก้ไขชื่อ/ไอคอน/สีของประเภทงานเดิม หรือ "ปิดใช้งาน" ประเภทงานที่ไม่ใช้
  แล้ว (ซ่อนจากฟอร์มแจ้งซ่อมใหม่ แต่ยังเห็นในรายงาน/ตัวกรองเหมือนเดิม ไม่กระทบข้อมูลเก่า) ไม่ต้องแก้โค้ด
  หรือ deploy ใหม่แต่อย่างใด
- แนบรูป **"หลังซ่อม" (After)** แยกจากรูป **"ก่อนซ่อม" (Before)** ที่ผู้แจ้งส่งมา ได้สูงสุด 5 ภาพต่อรายการ ในหน้ารายละเอียด/แก้ไขงาน — ใช้เปรียบเทียบก่อน-หลังซ่อม ผู้แจ้งก็จะเห็นรูปหลังซ่อมนี้ในหน้าติดตามสถานะของตัวเองด้วย
- ส่งออกรายการเป็นไฟล์ Excel ได้ (ปุ่ม "📊 ส่งออก Excel" — ส่งออกเฉพาะรายการที่กรอง/ค้นหาอยู่ ณ ขณะนั้น มี 2 ชีต คือสรุปตัวเลขและรายการทั้งหมด **พร้อมรูปภาพก่อนซ่อมและหลังซ่อมแสดงเป็นรูปย่อในไฟล์ Excel โดยตรง**)

## ภาษาที่ใช้ในแอป (Multi-language / 多语言)

ทั้งแอป (หน้าแจ้งซ่อมและหน้าแอดมิน) แสดงข้อความเป็น 3 ภาษาพร้อมกันในบรรทัดเดียวเสมอ รูปแบบ "English / ไทย / 中文" — ไม่มีปุ่มสลับภาษา ผู้ใช้ทุกคนเห็นครบทั้ง 3 ภาษาตลอดเวลา คำแปลทั้งหมดรวมศูนย์อยู่ที่ไฟล์ `js/i18n.js` ไฟล์เดียว หากต้องการแก้ไขคำแปลใดๆ (หรือเพิ่มภาษาที่ 4) แก้ที่ไฟล์นี้ได้เลย

ข้อควรทราบ: ค่าที่ใช้เก็บจริงใน Firestore (ประเภทงานใน collection "categories" / สถานะ / แผนกที่ส่งต่อ ใน `js/config.js`) ยังคงเป็นภาษาไทยเหมือนเดิมโดยตั้งใจ เพื่อไม่ให้กระทบข้อมูลที่มีอยู่แล้วหรือระบบกรอง/ค้นหา — ส่วนที่แปล 3 ภาษาคือ "ข้อความที่แสดงบนหน้าจอ" เท่านั้น ประเภทงานที่แอดมินเพิ่มขึ้นมาเองใหม่ (นอกเหนือจากที่มีคำแปลไว้ให้แล้วใน `js/i18n.js` → `CATEGORY_TRI`) จะแสดงเป็นภาษาไทยอย่างเดียวโดยอัตโนมัติ ไม่ error แต่อย่างใด — ถ้าต้องการให้มีคำแปล 3 ภาษาด้วย เพิ่ม entry ใหม่ใน `CATEGORY_TRI` เองได้ ชื่อชีต (worksheet) ในไฟล์ Excel ที่ส่งออกยังคงเป็นภาษาไทยล้วน (เพราะ Excel จำกัดชื่อชีตไม่เกิน 31 ตัวอักษร) แต่หัวตาราง/เนื้อหาภายในแปล 3 ภาษาแล้ว ส่วนชื่อบริษัทและที่อยู่ (`COMPANY` ใน config.js) ยังเป็นไทย/อังกฤษเหมือนเดิม ไม่ได้แปลเป็นจีนให้ เพราะเป็นข้อมูลทางการที่ควรได้รับคำแปลที่ถูกต้องจากคุณเองหากต้องการ

## การปรับแต่ง

- **โปรเจกต์** จัดการได้โดยตรงที่หน้าแอดมิน (หัวข้อ "📁 จัดการโปรเจกต์" ในแดชบอร์ด — เพิ่ม/แก้ไข/
  ปิดใช้งานได้ทันที ไม่ต้องแก้โค้ด) ไม่มีชุดข้อมูลเริ่มต้นตายตัวเหมือนประเภทงาน ต้องสร้างโปรเจกต์แรก
  เองก่อนผู้แจ้งจึงจะเลือกได้ในฟอร์ม
- **ประเภทงาน** จัดการได้โดยตรงที่หน้าแอดมิน (หัวข้อ "🗂️ จัดการประเภทงาน" ในแดชบอร์ด — เพิ่ม/แก้ไข/
  ปิดใช้งานได้ทันที ไม่ต้องแก้โค้ด) ส่วน `js/config.js` (`CATEGORIES_SEED`) เป็นเพียงชุดข้อมูลเริ่มต้น
  ที่ใช้ตอนหว่านเมล็ดเข้า Firestore ครั้งแรกเท่านั้น แก้ไขไฟล์นี้ทีหลังจะไม่มีผลกับระบบที่ใช้งานไปแล้ว
- แก้ไขรายการแผนกที่ส่งต่อได้ที่ `js/config.js` (`DEPARTMENTS`)
- แก้ไขชื่อบริษัท/ที่อยู่/เลขผู้เสียภาษีที่แสดงหัว-ท้ายหน้าเว็บได้ที่ `js/config.js` (`COMPANY`) — เปลี่ยนโลโก้โดยแทนที่ไฟล์ `assets/logo.svg` ด้วยไฟล์โลโก้จริงของบริษัท (จะใช้ไฟล์ `.png`/`.jpg` แทนก็ได้ แค่แก้ path ที่ `COMPANY.logo`)
- แก้ไขสี/ธีมได้ที่ `css/style.css` (ตัวแปร `:root`)
- ทดสอบในเครื่องก่อน deploy: รันเว็บเซิร์ฟเวอร์ในโฟลเดอร์นี้ เช่น `npx serve .` แล้วเปิด `http://localhost:3000`
